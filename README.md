# CallAmbulance — Emergency Ambulance Dispatch System

**Rapid medical response, callAmbulance.**

CallAmbulance is a full-stack, role-based **Emergency Ambulance Dispatch & Medical Transport Platform** designed to connect patients in critical need with nearby ambulance units and emergency medical drivers in real time. Built with the **Next.js App Router**, **TypeScript**, **Tailwind CSS**, **shadcn/ui**, **TanStack Query**, **Zustand**, **NextAuth.js**, and **Stripe Checkout**, the platform streamlines the entire lifecycle of an emergency medical dispatch—from emergency call creation and criticality-based vehicle allocation to live trip status tracking and online billing.

## How It Works (End-to-End Dispatch Workflow)

CallAmbulance coordinates three distinct user roles (**Patient**, **Admin**, and **Driver**) through a structured 6-step emergency response workflow:

1. **Fleet & Driver Setup (Admin):**
   - Administrators register ambulances in the fleet (`ICU`, `BASIC`, or `PEDIATRIC`), set their station address, and assign each vehicle to an individual **Driver**.
2. **Emergency Request Submission (Patient):**
   - A patient submits an emergency ambulance request specifying their contact phone number, pickup location, destination hospital, and **Criticality / Urgency Level** (`CRITICAL`, `HIGH`, `MEDIUM`, or `LOW`).
3. **Criticality-Based Ambulance Allocation (Admin):**
   - Administrators monitor incoming `PENDING` requests in real time and allocate an available ambulance with an assigned driver.
   - **Strict Criticality Matching:** `CRITICAL` and `HIGH` priority requests require **ICU** life-support ambulances, while `MEDIUM` and `LOW` requests are matched with **BASIC** transport units. Once dispatched, the request status changes to `ASSIGNED` and the ambulance status updates to `BUSY`.
4. **Live Emergency Status Updates (Driver):**
   - The assigned driver receives the dispatch in their Driver Dashboard and updates the emergency situation status step by step:
     - `ASSIGNED` → `EN_ROUTE` (En route to patient) → `PICKED_UP` (Patient on board) → `COMPLETED` (Delivered to destination hospital).
   - When marked `COMPLETED` (or `CANCELLED`), the ambulance is automatically released back to `AVAILABLE` for future dispatches.
5. **Post-Completion Billing (Admin):**
   - Once a dispatch reaches `COMPLETED`, the Administrator generates an itemized payment bill (`$ USD`) for the patient from the Admin Payments & Billing panel.
6. **Online Payment via Stripe & Real-Time Sync (Patient → All Roles):**
   - The patient sees the generated bill on their dashboard and pays securely via **Stripe Checkout (Test Mode)**.
   - Upon completion, the payment session is verified with the backend and the payment status updates to **Paid (`SUCCESS`)** across the **Patient**, **Driver (Earnings)**, and **Admin** dashboards simultaneously.

## Key Features by Role

### Patient (`PATIENT` — `/dashboard`)
- **Emergency Request Form:** Submit urgent dispatch requests with pickup address, hospital destination, phone number, and criticality level.
- **Live Booking Tracker:** View active and historical dispatches, assigned ambulance plate/type, driver contact details, and real-time status badges.
- **Stripe Online Billing:** View bills generated by Admin for completed trips and pay online via Stripe Checkout.
- **Profile Management:** Update personal details and emergency contact information.

### Driver / Provider (`DRIVER` — `/provider`)
- **Active Dispatches Queue:** View assigned emergency calls with pickup/destination details, criticality badges, and one-tap patient phone dialing.
- **Real-Time Status Control:** Update dispatch progression (`ASSIGNED`, `EN_ROUTE`, `PICKED_UP`, `COMPLETED`, `CANCELLED`).
- **Assigned Vehicles Management:** View assigned ambulances and toggle vehicle availability (`AVAILABLE`, `BUSY`, `MAINTENANCE`).
- **Earnings & Billing Overview:** Track total paid earnings, pending billed trips awaiting patient payment, and completed trip history.

### Administrator (`ADMIN` — `/admin`)
- **Emergency Dispatch Center:** Filter and sort all emergency requests by status, date, or criticality, and allocate matching available ambulances.
- **Fleet & Ambulance Management:** Create new ambulances (`ICU`, `BASIC`, `PEDIATRIC`), update vehicle types/statuses, and assign or reassign drivers.
- **Users & Role Management:** View all registered platform users and manage user roles (`PATIENT` / `DRIVER`).
- **Payments & Billing Control:** Generate and update bills for completed dispatches and monitor payment statuses (`UNBILLED`, `BILLED`, `PAID`).

## Technology Stack

### Frontend
- **Framework:** [Next.js 16](https://nextjs.org/) (App Router, Server & Client Components, Middleware Route Protection)
- **Language:** [TypeScript](https://www.typescriptlang.org/)
- **Styling & UI Components:** [Tailwind CSS v4](https://tailwindcss.com/), [shadcn/ui](https://ui.shadcn.com/), [Radix UI](https://www.radix-ui.com/) / Base UI, [Lucide Icons](https://lucide.dev/)
- **Data Fetching & Server State:** [TanStack React Query v5](https://tanstack.com/query/latest) + [Axios](https://axios-http.com/)
- **Global Client State:** [Zustand](https://zustand-demo.pmnd.rs/) (Responsive sidebar navigation & active role state)
- **Forms & Schema Validation:** [React Hook Form](https://react-hook-form.com/) + [Zod](https://zod.dev/) (`@hookform/resolvers/zod`)
- **Authentication:** [NextAuth.js v4](https://next-auth.js.org/) (Credentials Provider + Google OAuth `@react-oauth/google` + JWT session strategy)
- **Payments:** [Stripe Checkout](https://stripe.com/docs/payments/checkout) (`@stripe/stripe-js`)
- **Notifications:** [Sonner](https://sonner.emilkowal.ski/) toast notifications

### Backend API
- **Runtime & Framework:** Node.js, Express.js, TypeScript
- **Database & ORM:** PostgreSQL + Prisma ORM
- **Authentication & Security:** JWT Access/Refresh Tokens, bcrypt password hashing, role-based authorization middleware, Zod request validation
- **Payments:** Stripe Node SDK (`stripe.checkout.sessions`)

## Getting Started Locally

### 1. Clone the repository
```bash
git clone https://github.com/arpansarkar112/Emergency_Ambulance_Dispatch_System_frontend.git
cd Emergency_Ambulance_Dispatch_System_frontend
```

### 2. Install dependencies
```bash
npm install
```

### 3. Configure Environment Variables
Create a `.env.local` file in the root directory:
```env
NEXT_PUBLIC_API_URL=https://emergency-ambulance-dispatch-system-seven.vercel.app/api/v1
NEXTAUTH_SECRET=my_super_secret_jwt_token_for_nextauth_development
NEXTAUTH_URL=http://localhost:3000
NEXT_PUBLIC_GOOGLE_CLIENT_ID=your_google_oauth_client_id
```

### 4. Run the Development Server
```bash
npm run dev
```
Open [http://localhost:3000](http://localhost:3000) in your browser.

### 5. Build for Production
```bash
npm run build
npm start
```
